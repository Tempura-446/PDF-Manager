# ZPDF / PDF-Manager — Engineering Audit Report & Consolidated Defect Register

> **Source baseline**: `v0.61.1` (`92b917a8316f217567e4288a381cc7c192b47654`)
> **Validated post-remediation revision**: `447a664628f38479db052266b8e47e2c1d45d5cf` (`main`, after PRs #145–#148)
> **Audit date**: `2026-11-22`

---

## 1. Executive Summary

A full-repository technical audit and staged remediation was executed on ZPDF `0.61.1` across Phases 0–12 (Stages A–G). Every previously identified security, reliability, and release-integrity defect was reproduced or verified directly in the source code, targeted fixes were implemented with minimal blast radius, and **41 new regression tests** were added and verified locally and across all GitHub Actions CI platforms (`ubuntu-latest` Python 3.10 & 3.13, `windows-latest` Python 3.13, `macos` audit, `OCR/PDF-A/Office`, `e2e`, and `CodeQL`).

During the application-wide audit (Stage F), three additional defects not listed in the original prompt were discovered and remediated:
- **`API-001`**: Missing validation on `Content-Length` headers in `pdfmanager/gui.py` and `pdfmanager/server/common.py` (negative values bypassed `MAX_UPLOAD` via `rfile.read(-1)`; non-integers raised unhandled `ValueError`).
- **`SEC-005`**: `auditlog._clean_details()` scrubbed string values via pattern matching but did not redact values stored under sensitive key names (`user_password`, `owner_password`, `private_key`, `github_token`, nested dicts).
- **`PERF-001` / `DEP-001`**: `ocr._looks_grey()` used deprecated Pillow 14 `Image.getdata()` in a pure-Python pixel loop (`32.08 ms` per 1200×1600 image); replaced with vectorized NumPy (`24.33 ms`, `1.3×` faster, zero deprecation warnings).
